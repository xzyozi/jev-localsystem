# Gemma4 思考抑止・1トークン即時判定 実測検証レポート

- **実施日**: 2026-09-20
- **対象モデル**: 
  - `gemma4-12b-it-Q4_K_M:latest` (Ollama, 11.9B)
  - `gemma-4-py_coder:latest` (Ollama, 11.9B)
- **検証目的**: 思考機能（Thinking / CoT）を持つGemmaモデルにおいて、思考文生成に伴うオーバーヘッド（デコード遅延）を回避し、単一Forwardパス（1トークン判定）が可能かを実証する。

## 2. 正解性検証（Yes / No 分岐確認）

思考タグ事前注入（Prompt Prefill, `raw: true`）を用いて、意味の異なる質問に対する1トークン判定精度を確認。

```text
Q1: "Is ice cold? Answer with Yes or No."
  --> 出力: "Yes" (1トークン目, 130ms)

Q2: "Is ice hot? Answer with Yes or No."
  --> 出力: "No"  (1トークン目, 132ms)
```

---

## 3. 得られた技術的知見（アーキテクチャ境界へのフィードバック）

1. **思考モデルのデコードオーバーヘッドは完全回避可能**:
   - Thinkingモデル（Gemma4等）は、学習済みテンプレートにより `<start_of_turn>model\n` の直後は必ず思考ブロック `<thought>` を出力しようとする。
   - しかし、**「空の思考完了タグ（`<thought>\n\n</thought>\n`）」をモデル応答の先頭に事前注入（Prompt Prefill）** することで、モデルは思考完了済みと判断し、**思考文のデコード生成ループを1ステップも回すことなく、即座に判定結果トークン（Yes/No）を出力する**。
2. **PromptBuilder への要件確定**:
   - `PromptBuilder` は、モデルが Thinking 属性を持つ場合、モデル末尾に空の思考タグ（またはダミーCoT終了タグ）を自動注入する Prefill 責務を持つ必要がある。
3. **計算性能の実測値**:
   - 単一Forwardパスの所要時間は約 **130ms**（GPU: RTX 3060 12GB、12Bモデル）。
   - 数十〜数百トークンの思考文を生成する通常方式（数秒〜十数秒）と比較して、**90%以上の時間短縮** を達成。
