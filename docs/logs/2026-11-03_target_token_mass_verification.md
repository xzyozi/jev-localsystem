# 対象トークン確率質量の下限（MIN_TARGET_MASS）実機妥当性検証レポート

- **検証日時**: 2026-11-03
- **対象 Issue**: [#26 [検証] 対象トークン確率質量の下限(MIN_TARGET_MASS)の実機妥当性](https://github.com/xzyozi/jev-localsystem/issues/26)
- **検証環境**:
  - ホスト: macOS (Apple Silicon M3, 16GB Memory)
  - 推論バックエンド: Ollama (v0.40.13, Metal iGPU 加速)
  - 対象モデル:
    - **Tier 1 (主軸モデル)**: `qwen3:8b` (5.2GB)
    - **Tier 2 (軽量モデル)**: `phi4-mini:latest` (2.5GB)
  - 仮想環境: Python 3.12 (`uv`)

---

## 1. 検証目的と背景

PR #18 において、Zero-Decode 推論判定時にモデルが出力した次トークン分布の上位候補（`top_logprobs=10`）に対象トークン（Yes/No、A〜H、1〜5 等）が含まれる割合の合算値（確率質量）を計算し、`ResultMapper.MIN_TARGET_MASS`（既定 `0.1`）未満の場合は正規化を行わず `status="INCONCLUSIVE"` を返す安全保護機構を導入した。

本検証では、実機 Ollama 環境において以下を検証・評価した：
1. **質量の実測分布**: `qwen3:8b` と `phi4-mini:latest` におけるタスク別（Noul, Choice, Score, Multi-Label）の確率質量分布（最小値、5パーセンタイル、中央値、最大値）。
2. **誤検知（False INCONCLUSIVE）の有無**: 正常なプロンプト判定が確率質量不足により誤って `INCONCLUSIVE` に倒れていないか。特に日本語長文（〜4,000トークン）での減衰影響。
3. **思考抑制 Prefill の影響**: CoT 思考モデル（Qwen3）で思考抑制タグを意図的に外した場合の挙動。
4. **語彙マスキング（`logit_bias`）の対応可否**: Ollama `/v1/chat/completions` における `logit_bias` の実機動作。
5. **下限閾値の妥当性と調整要否**: `MIN_TARGET_MASS = 0.1` が最適か。

## 3. 分析と知見

### 3.1 正常時における対象トークン質量の極めて高い集中度
- **Qwen3 (8B)**:
  - 思考抑制 Prefill (`<think>\n\n</think>\n`) により、推論開始の第1トークンは 99.999% 以上の確率で対象トークン（`Yes`, `No`, `A`〜`H`, `1`〜`5`）に集中。
  - 日本語 12,000 文字（約4,000トークン）の長文コンテキストにおいても質量は `1.0000` を維持。
- **phi4-mini (3.8B)**:
  - 非思考モデルであり Prefill を注入しないが、プロンプト指示（「YesまたはNoのみを出力してください」等）に従い、全試行で **最小 0.9069（約90.7%）** の確率質量が対象トークンに配分された。
  - 日本語 12,000 文字の長文時でも `0.9678`（約96.8%）を維持。

### 3.2 誤検知（False INCONCLUSIVE）の有無
- 正常な入力において、確率質量が原因で `INCONCLUSIVE` に判定されたケースは **0件** であった。
- Choice タスクにおいて `status="INCONCLUSIVE"` となった試行（Qwen3 の `Choice_4Way_Framework`、phi4-mini の `Choice_Manner_Email`）が存在したが、これらは **A/Bスワップ位置バイアス照合（順序反転による拮抗検知）** による正常な安全引き分け動作であり、対象トークン質量はいずれも `1.0000` を記録している。
- したがって、下限値 `0.1` による誤検知は一切発生していない。

### 3.3 思考抑制 Prefill なし時の検証
思考モデルである `qwen3:8b` に対し、思考抑制 Prefill を付与せず同一プロンプトを投入した実験を実施：
- **生成された第1トークン**: `<think>` タグ
- **上位トークン候補**: `<think>`, `\n`, `Sure`, `I` など思考・前置きトークン
- **対象トークン（Yes/No）の確率質量**: **`8.24e-09`（≒ 0.0000）**
- **判定**: `ResultMapper.MIN_TARGET_MASS = 0.1` のチェックにより、正しく **`INCONCLUSIVE`** として遮断された。
- **考察**: もし下限チェックが存在しない場合、Top-10 に不在の極小対数確率（`FALLBACK_LOGPROB = -20.0`）同士で疑似正規化され、50%:50% のランダムなノイズ判定を SUCCESS として返却してしまう危険がある。`MIN_TARGET_MASS` はこの致命的欠陥を完全に防御している。

### 3.4 語彙マスキング（`logit_bias`）の実機対応調査
Ollama の `/v1/chat/completions` エンドポイントに対し、`logit_bias` パラメータを付与した推論リクエストを実機送信：
- **結果**: HTTP 200 で応答するものの、`logit_bias` の指定は **完全に無視される**（llama.cpp 側への適用なし）。
- **結論**: ローカル Ollama 環境では事前語彙マスキングが利用できないため、現行の **「`top_logprobs=10` の取得 → 事後フィルタリング・空白バリアント対数和計算 → `MIN_TARGET_MASS` による確率質量バリデーション」** のアーキテクチャが、最も移植性が高く堅牢な解である。

---

## 4. 結論と推奨

1. **下限閾値 `MIN_TARGET_MASS = 0.1` の維持**:
   - 正常判定時の最小質量: **0.9069**（90.7%）
   - 異常・対象外トークン出力時の質量: **~1e-8**（0.0000%）
   - 現行の `0.1`（10%）は、正常値と異常値の間に約 1 桁〜8 桁の安全マージンが存在し、モデル間差分（Qwen3 vs phi4-mini）を考慮してもモデル別に分岐させる必要はなく、単一のグローバル定数として極めて安全かつ適切である。
2. **設計書（JEV-DD-001）への反映**:
   - `docs/design/JEV-DD-001_推論判定パイプライン詳細設計書.md` 2.4節に、実機実測（Qwen3: 99.9%+, phi4-mini: 90.7%+）により `MIN_TARGET_MASS = 0.1` の妥当性が実証された旨を追記する。
