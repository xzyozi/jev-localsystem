# コンテキスト長限界 (Lost in the middle) 確信度減衰 実測レポート (Issue #6)

- **実施日**: 2026-09-20
- **対応Issue**: [#6: [検証] コンテキスト長限界（Lost in the middle）に伴う確信度低下の検証](https://github.com/xzyozi/jev-localsystem/issues/6)
- **対象モデル**: `qwen2.5-coder:14b-instruct` (Ollama, 14B)
- **実験条件**: ターゲットルールを長大テキストの完全な「中央（Middle）」に埋め込み、500文字〜12,000文字（約150T〜3,750T）まで段階的に拡張してLogitマージンを測定。

## 2. 判明した定量的知見

1. **確信度マージンの緩やかな減衰（耐性確認）**:
   - 最短文（156T）の $+6.75$ から、超長文（1875T）の $+5.69$ へと、**約 1.06 ポイントの確信度低下（注意の分散）** を観測。
   - 一方で、約3,750トークンに達してもマージンは $+5.7$ 以上を保っており、Qwen2.5-coderは中央埋め込み（Lost in the middle）に対しても非常に高い情報保持力を示した。
2. **真のボトルネックは「Prefill レイテンシ（計算時間）」**:
   - 精度（マージン）が崩壊するよりも遥かに早く、**プロンプト読み込み時間（Prefill Latency）が深刻なボトルネック** となる。
   - 1,000トークン未満であれば約3〜9秒で判定可能だが、3,750トークンでは **約38.6秒** を要した。

---

## 3. 設計（基本設計書 JEV-BD-001）へのフィードバック

- **VRAM Manager のリミッター閾値（Token Limiter）の確定**:
  - **推奨ソフトリミット（Soft Limit）: 2,000 トークン（約 6,000 文字）**
    - 判定レイテンシを実用範囲（約15秒以内）に収め、十分なマージン（+5.7以上）を保証する安全上限値。
  - **ハードリミット（Hard Cutoff）: 4,000 トークン（約 12,000 文字）**
    - これを超える入力は、推論エンジンに渡す前段で `PayloadTooLargeError` として弾き、システム全体の滞留・フリーズを未然に防止する契約を策定する。
